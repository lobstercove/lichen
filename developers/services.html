Services & Release Binaries

This page maps every user-facing runtime service and signed release binary to its source package, configuration contract, and deployment boundary. It is checked against the workspace and release workflow on every release.

Signed Release Boundary

Verify before installation
Install production-host binaries only from a published GitHub release. Verify SHA256SUMS, its detached ML-DSA signature SHA256SUMS.sig, the signer in deploy/release-trust-anchor.json, and GitHub artifact provenance. A local build is for development and qualification, never for replacing a live validator binary.

The public network is testnet. Mainnet has not launched; a fresh mainnet requires its own no-waiver genesis-to-tip archive proof, capacity approval, and signed launch handoff.

Archive V2 Lifecycle

  1. Build canonical, certificate-normalized segments from a coherent hot/cold source checkpoint.
  2. Verify deterministic segment and catalog roots locally and in both configured replica domains.
  3. Activate only a signed catalog whose admitted range and following boundary match canonical chain history.
  4. Prove every validator serves the same genesis-to-tip public-history manifest, subject only to an explicitly recorded network-specific waiver.
  5. Retire legacy rows only with a signed, exact-range authorization after V2 source and replica equivalence.
  6. Compact the retired RocksDB ranges, measure physical reclaim, and retain only the running signed release plus its signed rollback anchor.

Object storage is a replica and recovery domain, not a substitute for deterministic local serving. Source-backed recovery tails are removed only after all validators prove V2 parity.

Release Verification

Shell
node scripts/verify-release-checksums.mjs .
grep 'lichen-validator-linux-x86_64.tar.gz' SHA256SUMS | sha256sum -c -
gh attestation verify lichen-validator-linux-x86_64.tar.gz -R lobstercove/lichen

After installation, verify the extracted, installed, and running executable hashes independently. See the Validator Guide for service hardening and the Architecture Guide for consensus and storage behavior.
