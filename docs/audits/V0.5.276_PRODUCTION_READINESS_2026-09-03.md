# v0.5.276 Production-Readiness Addendum

Date: 2026-09-03

Status: release candidate. This is not deployment approval until protected CI,
the immutable exact-tag workflow, all four-validator Archive V2 gates,
provenance, checksums, the detached ML-DSA signature, coordinated installation,
and live acceptance pass.

## Trigger

Immutable `v0.5.275` passed protected PR CI and every release job except the
exact-tag four-validator Archive V2 gate. Fresh full-archive V3 authenticated
and imported the slot-10,000 checkpoint, rebuilt the bounded categories,
created its local checkpoint, and completed sync bookkeeping. It then exited
with status 0 during deferred Archive V2 admission. Release workflow
`33786039404` consequently skipped checksums, signing, and publication. No
`v0.5.275` artifact was deployed.

Snapshot materialization already serializes against cold archive maintenance,
but that lock was released before deferred role admission. By then the cold
migration scheduler and canonical block receiver were active, allowing either
to change the hot/cold handoff while admission scanned it. The admission error
branches logged through the nonblocking tracing worker and returned from the
validator future, which could lose the final message and produce a successful
process status.

## Narrow correction

- Mark deferred Archive V2 admission pending before the cold migration
  scheduler starts and keep migration paused until admission succeeds.
- Hold the canonical block-application lock while deferred admission verifies
  and binds the imported hot/cold suffix.
- Clear the pending state only after a capability is admitted.
- On failure, write the exact diagnostic synchronously and exit nonzero.

This does not change consensus, state transitions, migration bytes or cursors,
checkpoint/catalog schemas, Archive V2 object format, role policy, retention,
or any validator's preserved state. It closes one lifecycle race and makes the
failure boundary observable.

## Production boundary

The live fleet remains on signed `v0.5.274`. Do not install a local candidate
or treat three-validator finality as complete recovery. Only an exact
`v0.5.276` tag artifact that passes every hosted gate and carries verified
provenance, checksums, and detached PQ signature may be installed. Installation
is one coordinated four-host stop/install/start preserving each host's own
keys, identity, WAL, state, cold archive, and rollback anchor. Archive V2
retirement and R2 deletion remain unauthorized until four-way own-state
convergence and genesis-to-tip parity are recorded.
