# v0.5.273 Production-Readiness Addendum

Date: 2026-09-03

Status: superseded and not deployed. The protected PR merged, but immutable
`v0.5.273` failed closed in its first strict four-validator Archive V2 tag gate
when fresh verified-cache V3 exited after importing checkpoint slot `20,000`.
A same-commit rerun later passed the complete workflow, establishing an
intermittent lifecycle failure rather than a deterministic archive or chain
failure. No detached operator ML-DSA signature was issued and no release was
accepted for deployment. `v0.5.274` carries the diagnostic and
rollback-lifecycle successor work.

## Production evidence

Signed `v0.5.272` is installed on all four Testnet validators. US, SEA, and IN
advance the preserved chain with quorum. EU fails closed at slot `12,263,310`
on a parent post-state-root mismatch and is waiting for an authenticated
checkpoint with two independent matching source attestations. Validator keys,
identities, WAL, state, legacy history, Archive V2 inputs, R2 objects, and the
signed `v0.5.265` rollback anchor remain preserved.

The slot `12,272,000` checkpoint attempt exposed two production-scale failures:

1. `FullArchiveV1` cannot package the live legacy cold placement because the
   checkpoint tree rejects symlinks and cross-filesystem hard links.
2. `v0.5.272` pre-activation `HotRepairV1` admission sums all inherited
   public-history SST allocation and doubles it. On US this converted
   `113,117,166,227` input bytes into a `226,234,332,454`-byte write estimate,
   even though RocksDB raw checkpoints hard-link inherited SSTs and allocate no
   duplicate data blocks for them.

The 30,000-slot release fixture exercised the correct logical behavior but did
not reproduce 12 million blocks, production filesystem placement, or this
whole-input estimate. The escape is therefore release-fixture scale and
topology coverage, not evidence of state corruption.

## Narrow correction

- `HotRepairV1` without an Archive V2 catalog root is eligible at the ordinary
  1,000-slot checkpoint cadence. Once a catalog root is bound, physical
  compaction remains limited to the existing 10,000-slot cadence.
- Admission retains the runtime disk floor, 8 GiB checkpoint envelope, 1 GiB
  mutable-write reserve, and 1 GiB WAL reserve.
- Materialization starts from a raw hard-linked checkpoint and accounts only
  newly emitted bounded rows. Every row includes key length, value length, and
  128 bytes of conservative overhead; the cumulative logical total is charged
  twice for import/WAL SSTs and compaction output, plus a fixed 1 GiB metadata
  envelope.
- The budget is checked before each page import. Exceeding it aborts the hidden
  staging directory; no checkpoint is published and live state is unchanged.
- The existing whole-input estimator remains available only as a diagnostic
  worst case and is no longer used for production checkpoint admission.

## Focused verification

- `hot_repair_materialization_budget_counts_only_new_bounded_rows` proves exact
  bounded accounting and that a rejected page does not consume the accumulator.
- `hot_repair_materialization_budget_fails_after_raw_capture_without_publication`
  proves consensus is released after exact raw capture and a budget failure
  removes both staging and publication paths.
- `hot_repair_checkpoint_cadence_bounds_physical_compaction_frequency` proves
  pre-activation eligibility at 1,000 slots and catalog-bound compaction only at
  10,000 slots.
- Archive parity asset QA asserts production uses budgeted per-page admission,
  does not call the whole-input estimator, and retains both cadence modes.

The immutable release workflow remains authoritative for formatting, Clippy,
workspace tests, dependency/security policy, standalone contracts and genesis
WASM, frontend/SDK/deployment QA, and the complete four-validator hot/cold
Archive V2 matrix with fresh joins, outage, own-state restart, coordinated
restart, DEX/CLOB/AMM, prediction, governance, launchpad, and public-history
parity.

## Deployment and recovery boundary

Only tag-workflow artifacts with verified checksums, provenance, and detached
ML-DSA checksum signature may be installed. The consensus-critical successor
uses one coordinated all-four stop/install/repair/start. Never deploy a local
build or mix validator versions.

After installation, two healthy sources must independently agree on the exact
checkpoint slot and state root before EU downloads and verifies a source-pinned
snapshot. EU resumes from its own preserved identity and WAL; no reset or raw
state-directory copy is authorized. Four-way fixed-slot/hash parity, RPC and
WebSocket health, live DEX/launchpad journeys, and genesis-to-tip Archive V2
logical parity are required before source-backed range retirement.

No ad-hoc legacy deletion or R2 deletion is authorized. Reversible legacy SST
offload may remain on checksum-verified read-only backup volumes until signed
Archive V2 retirement proves that every retained range is independently
recoverable.
