# Account Activity pagination

## Problem and scope

`getTransactionsByAddress` requests one more account-index row than the displayed
page to determine `has_more`. The StateStore account query merged its hot and
legacy-cold rows with every Archive V2 account index before sorting and limiting
the result. On the deployed 443-segment catalog, the bounded request could scan
all older index frames even when recent rows already filled the page.

Signed v0.5.290 live probes of a sampled historical oracle account exceeded a
30-second request deadline on US and SEA; warm EU and IN probes took about
5.8 and 17.3 seconds. These are sampled RPC measurements, not measurements of
the reporting user's wallet. The earlier wallet service-worker response repair
is separate and is already deployed.

## Change

The account query now sorts, deduplicates and limits its local candidates first.
It visits authenticated archive ranges in descending slot order and merges each
range before deciding whether older ranges can contribute. Once the page is
full, a range ending strictly below its oldest slot cannot change that page.
The boundary slot remains inclusive, preserving other transaction ordinals at
the same slot and exact duplicate handling across hot/archive overlap.

The reader continues to resolve active supersession manifests and authenticate
requested index frames. Required archive failures propagate; an empty range
does not terminate a partial page. Consensus-role queries retain their hot-only
behavior. No consensus, storage format, wire format, cursor shape, counter,
custody or wallet signing behavior changes.

## Regression coverage and deployment gate

- A state fixture covers a full hot page without archive fetches, a partial page
  filled from the newest archive range, within-slot cursors, empty account
  ranges, genesis and maximum-slot boundaries, overlapping hot/archive rows,
  and failure when an unavailable older range becomes necessary.
- The wallet RPC fixture requests two consecutive 20-row pages through the
  actual handler, including its extra `has_more` row, receipts and timestamps.
  Both pages must make zero requests to the unavailable older archive source.
- Existing exact-cursor and core/RPC suites remain required, together with the
  unchanged release CI, signed artifact and four-validator gates.

Before claiming the live latency regression resolved, repeat the same sampled
RPC requests after signed deployment and record cold/warm timing, returned
signatures, ordering, pagination and error behavior. Measure the actual user's
account only when that address is available. A new-account query with too few
rows may legitimately inspect every archive range to prove exhaustion; this
change does not promise constant latency for all historical queries.
