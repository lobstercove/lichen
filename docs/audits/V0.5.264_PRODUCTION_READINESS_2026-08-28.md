## Withheld activation boundaries

- Legacy shielded scheme `0x01` is disabled fail-closed. Public history remains
  readable, but private proof generation, verification, submission, CLI, and
  wallet actions stay disabled. No privacy claim is authorized until a new
  ownership-binding scheme is independently reviewed and versioned.
- Existing-network Staking V2 activation requires an exact live pre-state,
  owner confirmation, a common future epoch boundary, deterministic dry-run on
  all four preserved databases, and at least one complete post-activation epoch.
  Shipping the binary does not activate the marker.
- No Accounting V2/V3 contract migration is implicit in the binary release.
  Each migration requires its own fixed source snapshot, governed pause/seal/
  completion, source-bound manifest, custody proof, receipts, and post-state
  parity.
- Archive V2 roles, legacy retirement, storage reclamation, and R2 deletion are
  not activated by this qualification. Exact role/capacity gates and separate
  deletion authorization remain mandatory.

## Remaining signed-testnet gates

PR #44 merged through an admin-enforced, linear-history `main` policy after all
14 required hosted checks passed. Its post-merge run exposed deprecated Node 20
action runtimes that GitHub was force-running on Node 24. PR #45 replaced every
affected pin with a reviewed Node 24-capable action, passed 14 hosted checks
with the expected PR-only Docker skip and zero annotations, and merged as
`a1f99a8f1f6bf766cfc3a09c721e3a59581c8ac5`. OpenSSF Scorecard passed on that
exact commit. The post-merge CI then exposed a deterministic Dockerfile drift:
the root workspace included `moss-provider`, but the image build did not copy
its manifest/source or the local `sdk/rust` path dependency. Release work again
stopped before tagging. The correction makes the Docker cache build strict,
covers every current default lib/bin target, and runs the real Docker build on
pull requests as well as `main` pushes.

   Build in branch protection, pass the complete protected PR matrix including

   and the zero-deprecation-annotation audit before fixing the release commit.
2. Create the exact annotated v0.5.264 tag from that commit,
   and pass the release workflow, including its clean four-validator run.
3. Download only workflow-produced artifacts, verify checksums and GitHub
   attestations, attach the detached post-quantum checksum signature, and keep
   the release draft until live acceptance.
4. Perform bounded read-only fleet preflight. Fail closed on artifact, hash,

5. Stage the signed artifact and use one coordinated four-host
   stop/install/start. Preserve v0.5.263 rollback material and prohibit a

## Mainnet blockers

Mainnet remains blocked until the live candidate has sustained SLO evidence,
the archive plane has durable capacity and independent failure domains for
genesis-to-tip retention, signed artifact and rollback operations are rehearsed,
and every production dependency/admin surface is fail-closed. Privacy cannot be
advertised while only the disabled legacy scheme exists. Any existing-state
Staking V2 or contract migration requires separately accepted governance and
replay evidence. The current 200 GB validator storage profile is not approved
for mainnet or indefinite archive growth.

## 2026-08-29 live preflight and public-claims addendum

Read-only live preflight found that the four-validator testnet is not currently
deployable:

- EU and India are stopped at the validator's 5 GiB absolute disk-headroom
  floor (about 4.8 GiB remained on each root); US and Singapore remain active
  but hold only 400,000 of 800,000 stake and therefore cannot form a two-thirds
  quorum;
- US and Singapore are stalled at slot 12,266,299, the public API reports no
  healthy origin, and the active roots have about 23 GiB and 8.5 GiB free;
- all four installed binaries are signed v0.5.263 with SHA-256
  `1d8f5277b47cdc0e5741ab096a9c76b2b9999ee045cebad1ea61591782301946`;
- the Archive V2 catalog observed before the halt did not yet cover the full
  retirement-eligible tail, so role bootstrap is not authorization to retire
  or delete legacy data.

No validator was stopped, restarted, wiped, copied, or modified during this
preflight. Recovery and v0.5.264 deployment require workflow-produced signed
artifacts, an exact capacity/catalog plan, preserved v0.5.263 rollback, and the
one-host-at-a-time Archive V2 admission/retirement sequence after coordinated
binary installation. No R2 deletion is authorized.
