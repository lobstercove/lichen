## Corrective boundary

The final parity gate previously hashed only the physical hot database. That
made equally complete validators disagree after choosing different valid
Archive V2 retirement handoffs. v0.5.266 computes one authenticated logical
manifest over the Archive V2 prefix and hot checkpoint suffix. Catalog-bound
`hot_repair_v1` checkpoints and pre-activation unbound checkpoints retain their
distinct admission rules. Missing coverage, overlap, discontinuity, catalog
root mismatch, or parent-hash mismatch aborts the operation.

The implementation reads each authenticated range once rather than performing
one point lookup per slot. Unit coverage proves that distinct physical
handoffs with the same canonical history produce the same final manifest; the
clean four-validator gate proves that behavior across independent nodes.

## Release and live testnet gates

The release sequence is intentionally fail-closed:

1. Review the complete diff, commit it cleanly, and pass every required
   protected `main` check on that exact revision.
2. Create the immutable annotated `v0.5.266` tag from that revision. The tag
   workflow must repeat the Linux four-validator gate, build every supported
   archive, publish checksums, and attest provenance.
3. Verify the workflow artifacts locally, attach the detached ML-DSA checksum
   signature, and keep the GitHub release draft while live acceptance runs.
4. Preserve the current signed rollback anchor, validator identities, keys,
   WAL, state, archive sources, and access configuration. Install the same
   verified Linux artifact with a coordinated stop/install/start; a
   consensus-critical mixed-version rollout is prohibited.
5. Prove installed/running hashes, signer and configuration preservation,
   four-voter BFT readiness, advancing common slots/hashes, RPC/WebSocket
   acceptance, restart/rejoin behavior, and logical genesis-to-tip Archive V2
   parity before publishing validator, wallet, or exchange releases.

## Archive V2 retirement and storage

The live migration is retroactive only when signed, range-bound Archive V2
catalogs cover the retired legacy ranges and every validator proves the same
logical history. Obsolete caches, staging directories, superseded checkpoints,
and redundant recovery copies may be removed after verification. Each host
keeps the current signed release and the required signed rollback anchor. The
US source-backed recovery tail remains until four-way V2 parity is proven.
Legacy hot/cold history is retired only through the signed range-bound command
and compaction; no manual deletion substitutes for that proof.

R2 is a migration and recovery source, not the canonical consensus database.
No R2 deletion is authorized by this review. Deletion requires the separately
recorded four-way live parity, rollback, recovery, and retention decision.

The current 200 GB fleet remains unsuitable for indefinite growth or mainnet.
Archive V2 bounds duplicated hot history and makes cold immutable history
portable, but it does not turn finite disks into permanent archive capacity.

The final bounded testnet topology is four equal-policy `verified_cache`
validators: identical catalog, 100,000-slot hot retention, authenticated
primary/replica source policy, object-size bound, and 2 GiB hard cache quota.
Request-driven cache contents may differ without changing logical history.
Every host must independently return a `Normal` capacity decision before final
activation; otherwise activation remains blocked rather than weakening a floor.

## Withheld activations

- Mainnet remains blocked pending a separately approved network genesis,
  durable independent archive capacity, operational rehearsal, and sustained
  live evidence.
- Existing-state staking and accounting migrations require their own governed
  snapshots, deterministic dry runs, activation boundaries, receipts, and
  post-state parity. Shipping a binary does not activate them.
- Shielded scheme `0x01` remains disabled.
- Archive retirement, R2 deletion, bridge-route publication, Moss provider
  publication, and exchange publication each retain their independent live
  gates.
