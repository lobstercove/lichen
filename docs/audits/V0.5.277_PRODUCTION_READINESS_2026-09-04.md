# v0.5.277 Production-Readiness Addendum

Date: 2026-09-04

Status: release candidate. This is not deployment approval until protected CI,
the immutable exact-tag workflow, the four-validator Archive V2 gate,
provenance, checksums, the detached ML-DSA signature, coordinated four-host
installation, and live acceptance all pass.

## Exact v0.5.276 failure

Immutable `v0.5.276` was not signed, published, or deployed. The exact-tag
four-validator gate passed catalog construction, four-way parity, checkpoint
materialization, and authenticated fresh snapshot transfer. Fresh full-archive
V3 imported checkpoint slot `10,000`, rebuilt its local checkpoint, and then
failed closed during deferred role admission:

```text
Archive V2 full-archive role requires a complete local hot/cold handoff
5001..=10000: canonical block 5001 is missing from local hot/cold storage
```

That checkpoint correctly retained slots `7,999..10,000`; its configured local
Archive V2 catalog already owned `0..7,998`. Admission independently derived
slot `5,001` from the fresh joiner's 5,000-slot retention setting and wrongly
required Archive-V2-owned slots `5,001..7,998` to remain duplicated in legacy
hot/cold storage.

The release quality job independently failed closed because the npm audit
endpoint returned HTTP 503. No dependency finding was reported, but signing
correctly remained blocked.

## Live v0.5.274 liveness incident

The signed four-validator fleet later stopped finalizing at height
`12,322,667`. US, SEA, and IN remained aligned at slot `12,322,666`; EU was
still behind at `12,263,310`. P2P announcements and gossip remained healthy,
but proposal builders occupied their consensus event loops for minutes:

- SEA: 14 transactions in 99.298 seconds, 3 in 193.821 seconds, 14 in
  620.281 seconds, and—after unrelated CPU cleanup—11 in 365.683 seconds;
- IN: 14 transactions in 184.127 seconds, 3 in 169.076 seconds, and 10 in
  237.288 seconds; and
- US: 9 transactions in 581.802 seconds.

Each VPS also had two orphaned Binance stream processes consuming one core
apiece. Those exact eight processes were terminated without touching validator
processes, state, mounts, or services. Consensus remained stalled, proving they
amplified but did not cause the defect.

Proposal construction correctly prefiltered the mempool through
`has_hot_transaction`, but nested speculative execution repeated duplicate
detection through `StateBatch::has_transaction`. That method falls through from
hot RocksDB to legacy cold transaction SSTs. The live cold SSTs are still
R2/FUSE-backed, so each ordinary new-transaction miss could synchronously wait
on remote object I/O inside the BFT event loop.

## Corrections

- Full-archive admission verifies the mutable hot/cold suffix beginning at the
  first slot outside the authenticated local Archive V2 catalog.
- Verified-cache and consensus roles retain the configured physical hot-window
  requirement because they cannot use a full local archive as their recent
  consensus-history substitute.
- Catalog coverage is still required through the slot immediately before the
  selected local suffix, and the catalog-tip/handoff parent hash remains
  fail-closed.
- Speculative duplicate detection checks the transaction overlay first and the
  consensus-active hot transaction family second; it never consults cold
  history. Canonical execution and public historical queries retain full
  hot/cold lookup behavior.
- Transactions protected by a valid recent blockhash remain hot longer than
  the replay window. Durable-nonce and EVM replay protection remains enforced
  by canonical account nonce state.
- Production startup fails when configured hot retention is below 301 slots,
  so the 300-slot recent-blockhash replay window cannot be migrated to cold.
  The 50,000-slot production and Archive V2 default is unchanged. Smaller
  windows remain available only in explicit local-development archive tests.
- npm audit receives three bounded attempts only for recognized registry or
  network availability failures. Vulnerability findings fail immediately; an
  unavailable service after the final attempt also fails the release.

This changes which storage tier speculative consensus execution may consult;
it does not change deterministic state transitions, replay rules, wire
compatibility, checkpoint or catalog schemas, Archive V2 segment bytes,
migration, compaction, retention, or any validator's preserved state.

## Verification

The regression reproduces the exact failed topology:

- immutable Archive V2 catalog: `0..7,998`;
- bounded checkpoint: `7,999..10,000`;
- full-archive role setting: 5,000 recent slots; and
- no legacy hot/cold copy of slot `5,001` before admission.

It fails with the v0.5.276 slot-5,001 diagnostic before the correction, then
passes after the correction and serves slot `5,001` from authenticated Archive
V2. All focused `archive_v2_` validator tests also pass. The full protected and
immutable release matrices remain required.

The speculative replay regression first migrates a known transaction out of
hot storage, proves the public historical lookup still finds it in cold, then
executes it speculatively. The corrected path does not classify it through cold
history; it reaches the unchanged replay guard and fails because its recent
blockhash is too old. This directly protects the production failure boundary.
An additional configuration regression proves that 300 production slots fail
closed, 301 pass, and low-retention stress testing requires explicit local
development mode.

## Production boundary

The live fleet remains on signed `v0.5.274`; `v0.5.265` remains the immediate
restart-safe rollback anchor. Do not install this local candidate. Only signed
exact-tag `v0.5.277` artifacts whose checksums, provenance, and detached PQ
signature verify may enter the coordinated four-validator deployment. Preserve
each validator's keys, identity, WAL, state, cold archive, and rollback anchor.
Legacy retirement and R2 deletion remain unauthorized until four-way
own-state convergence and genesis-to-tip Archive V2 parity are recorded.
