## Gate evidence and failure boundary

Immutable `v0.5.273` passed protected PR `#56`, release quality and security,
standalone contracts, compiler sandboxing, and all platform artifact builds.
Its first strict four-validator Archive V2 tag gate failed during the fresh
`verified-cache` V3 join. V3 authenticated and imported verified checkpoint
slot `20,000`, rebuilt the bounded local checkpoint, updated sync bookkeeping,
and then exited. The last captured line was checkpoint activation; the next
synchronous operation in that control-flow path was rollback-transaction
cleanup. The captured output contained no panic, root mismatch, no-space error,
OOM report, signal, or final fatal reason. The gate checked only process
existence, did not wait for and report the child status, and direct fatal exits
were written only through a non-blocking tracing sink. That evidence localizes
the failure boundary but does not invent an unavailable OS exit reason.
`v0.5.273` was not signed or deployed.

A same-commit rerun of tag workflow `33707476951` subsequently completed all
jobs successfully, including four-validator Archive V2 job `100513883994`.
An independent exact local reproduction also crossed the original boundary:
fresh full-archive V3 admitted at slot `21,431`; fresh verified-cache V3
imported checkpoint `20,000`, admitted at network slot `22,026`, served
verified genesis history, failed deep history closed during an authenticated
source outage while consensus produced 22 blocks in 10 seconds, and refetched
after source recovery. A direct process watcher observed no rollback or staging
sidecar after the harness intentionally stopped that successful node. Peak RSS
was 868,512 KiB and minimum available local disk was 54,627,852 KiB. This
establishes that the first exit was intermittent; it does not make the missing
exit reason acceptable or remove the unsafe pre-correction ordering.

## Narrow correction

- Snapshot import remains guarded by a hot RocksDB rollback checkpoint and a
  durable transaction marker.
- The imported state is not exposed as live in sync bookkeeping until rollback
  checkpoint and marker cleanup succeeds.
- Cleanup is idempotent and retried five times across transient filesystem
  errors. Parent directory fsync is repeated even when a retry observes that a
  prior attempt already removed an entry.
- A persistent failure still terminates the validator fail-closed, but the
  complete reason is written synchronously to stderr before exit.
- The four-validator gate waits for the child status, reports any remaining
  rollback sidecars and filesystem headroom, and rejects healthy role admission
  if a snapshot transaction is still pending.
