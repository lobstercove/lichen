## Exact finding

Release run `33904038631` for immutable tag `v0.5.279` passed every completed
quality, security, contract, compiler, and platform-build job. Its local
four-validator Archive V2 job also passed the strict 147/147 DEX, CLOB, AMM,
prediction-market, and user journeys and the 104/104 launchpad and governance
journeys. The runner canceled that job at its configured 90-minute limit while
the gate was verifying block production after V4's successful post-activity
own-state restart. There was no failed assertion. Checksum generation and draft
release creation were therefore skipped, so `v0.5.279` has no deployable
artifact.

This is a release-harness duration defect, not an Archive V2 data, consensus,
MossStake repair, DEX, prediction-market, governance, or launchpad regression.
The exact cancellation occurred after the exercised application suites were
green and while the validator cluster was still advancing.

## Narrow successor

`v0.5.280` changes only the following release boundary:

- the exact-tag four-validator Archive V2 job limit is 150 minutes instead of
  90 minutes;
- workspace package and public candidate versions advance to `0.5.280` so the
  failed immutable tag is never moved or reused;
- the WAL-preserving rollback and deterministic slot-`12,333,500` legacy
  Testnet MossStake activation are unchanged from the reviewed `v0.5.279`
  implementation.

No BFT algorithm, state-transition rule, wire or block encoding, checkpoint,
catalog, migration, compaction, or Archive V2 object format changes in this
successor. Fresh testnets and mainnet still cannot enter the guarded legacy
Testnet repair path.

2. The immutable `v0.5.280` tag workflow must complete every job, including the

   preflight succeeds, receive the same signed artifact, restore the exact

5. Live evidence must prove the deterministic repair boundary, at least 1,000
   later commits, four-validator artifact and state parity, Archive V2

non-transferable. No reset, state copy, WAL replacement, or R2 deletion is
