# v0.5.281 Archive V2 query runtime qualification

Status: candidate; protected CI, immutable signed release, complete local
four-validator and production acceptance remain mandatory.

Signed v0.5.280 admitted Archive V2 on all four validators, then failed runtime
acceptance and recovered to the preserved baseline. Its internal gateway TLS
and checkpoint-capacity corrections passed independent checks. A complete hot
recent-transaction page nevertheless fetched older archive objects, while
synchronous aggregate queries occupied the shared async executor.

The exact-tag complete-hot-page regression fails with one unnecessary remote
fetch. A separate single-worker regression uses an explicitly hot tip at slot 1,
an archived genesis at slot 0 and a delayed authenticated source. An account
query prevents getSlot responding within 250 ms on the original tag. Both
regressions pass with the candidate. The production stack was stripped; it
does not identify the exact initiating live request.

The correction bounds blocking RPC work to four jobs. Permits remain in the
blocking job after client cancellation; saturation returns 503/-32005. Existing
authentication and mutation rules remain enforced. Recent pagination starts its
archive scan at the oldest selected hot slot when its page is full, preserving
same-slot overlap, deduplication and exclusive cursor semantics.

Aggregate queries use authenticated index bundles within the existing object
cache quota. The original envelope, dictionary and public-index frame hash bind
each bundle to the independently authenticated catalog. Selected decoding
checks every key's ordering, row bounds and frame reference while avoiding
unneeded row/location allocations. This is a disposable cache format, not a
change to archive objects, catalogs, checkpoints, wire encoding or consensus.
Index availability never proves unavailable block bodies or complete-object
integrity; complete public-history audits and source-outage acceptance remain
separate gates.

The prewarm command binds actual identity, authenticates every selected source
index before cache writes, checks quota plus reserve, and verifies every cached
entry afterward. Tests cover incorrect identity, insufficient quota, damaged
source/cache data, skipped-row corruption, cancellation, concurrency, shared
eviction, dry-run and idempotent execution. The 388-segment Testnet catalog
requires 708,544,223 index-cache bytes. Its first cache prototype still took
roughly 9.6 seconds per account query; production-size measurements therefore
remain part of qualification rather than inferring performance from fixtures.
Selected decoding and reusable key buffers reduced the same local
production-catalog queries to 5,158..5,435 ms with zero remote fetches and
unchanged results. This is a local measurement, not a fleet latency guarantee.
Live acceptance must measure concurrent traffic and finality on the signed
release before activating the archive roles.

Require fresh current finality and authorship under representative recent,
aggregate, historical, transaction and proof traffic. Complete the exact
four-validator hot/cold, fresh-join, outage, own-state and coordinated restart
matrix, all release gates and the final production history/application checks.
Install only final tag-workflow artifacts whose detached PQ signatures and
installed/running hashes verify. Preserve signed v0.5.280 and v0.5.265 rollback
artifacts and every validator's own state, identity, keys, WAL and cold archives.
