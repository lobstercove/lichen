## v0.5.269 hosted failure evidence

PR 52 and post-merge CI passed at commit
`7a53952b0a5b8de631ba74f00e8a28e9f5e3aa1c`. Release workflow
`33589842830` passed the release quality, security, compiler, genesis, and
complete four-validator Archive V2 matrix. The Archive V2 job then failed in
the later strict volume journey when the Phase 11 matched DEX buy returned ABI
code 11. No platform artifacts were built and no validator was mutated.

The failure was an expired controlled oracle input, not Archive V2 or compute
exhaustion. The hosted network was at slot 25,763 when the volume journey
started and refreshed LICN/USD at slot 34,481. It advanced an average 8,718
slots in 357.16 seconds, about 24.4 slots per second. Phase 11 ran 34.26
seconds after the refresh, enough for roughly 836 slots and therefore beyond
the DEX contract's strict 750-slot price-band lifetime. ABI code 11 is the
documented fail-closed result for an unavailable, malformed, future, or stale
band.

The same journey on the local four-validator network proved Dave's lUSD
balance and allowance exceeded the required escrow, and the matched buy
committed successfully at slot 25,420. Its receipt records 47,543 compute units
against the default 200,000-unit budget, ruling out the preliminary compute
exhaustion hypothesis.

## Narrow correction

The strict volume journey now submits the controlled LICN/USD price from every
active local validator again immediately before Phase 11. It waits for and
reads back both deterministic post-block consumers: the margin mark and the
DEX spot-band price/source slot. Both must equal the requested value, derive
from the new minimum source slot, be no more than 750 slots old, and be
non-future. No admin storage override, relaxed age, extra balance, or test-only
contract path is used.

The Phase 11 buy also records the required token escrow, exact balance, exact
allowance, and a bounded simulation result before submission. RPC contract
preflight failures now include the ABI return code, compute used/requested, and
up to four sanitized 256-character trailing contract logs. These diagnostics
are non-consensus and bounded.

A source QA regression requires the second quorum refresh to occur after the
Phase 11 boundary and before the WebSocket trade, and requires the helper to
read and validate `dex_band_{pair_id}`. A frontend QA regression preserves the
existing protocol-maximum compute budget for real DEX contract transactions;
that existing client behavior is defense in depth and was not the hosted
failure's cause.

## DEX, launchpad, governance, and prediction-market audit

The release scope was expanded after the hosted failure to review custody and
state transitions across the full launch DEX rather than merely make the
failed journey pass. The review found and corrected independent latent defects
that were not causes of the v0.5.269 Archive V2 workflow failure.

DEX Core now transfers taker input into escrow before matching and treats every
maker/taker settlement failure as transaction failure. Expired and self-trade
orders return maker escrow, completed orders return residual escrow, maker
rebates come from the taker fee, protocol fees receive only the remainder, and
positive maker fees are rejected. Buy escrow includes the proportional fee and
per-lot floor, the order-cap counter tracks live orders with legacy migration,
shallow market-sell quotes report actual executable fill/refund, and stop
orders activate only from the canonical last trade. The new read-only exact-in
quote gives the router real CLOB output without mutating an order book.

DEX AMM quotes no longer mutate fee-growth state. Exact-output search uses the
same concentrated-liquidity tick-crossing curve as execution, accounting
overflow fails before custody transfer, and swaps authorize either the trader
or a one-time configured router. DEX Core has the same immutable router binding.

The router now indexes venue and direction separately instead of treating a
pair as one undirected route. Both token directions work, one CLOB and one AMM
route can coexist per direction, split and multi-hop routes validate their
token chain, direct routing quotes both venues and chooses the best output, and
all split/counter arithmetic is checked. Fresh genesis binds the router into
Core and AMM and registers all 13 launch pairs in both directions on both
venues (52 routes). SporePump graduation records directional AMM routes only
after its existing atomic pair, pool, inventory, deposit, dust, and burn checks
pass.

DEX governance now rejects identical-token pairs, positive maker fees, and a
maker rebate whose magnitude exceeds the taker fee. Emergency delisting is
recorded only when the Core pair pause succeeds. The prior requirements-only
listing entry point is retained for wire compatibility but fails explicitly as
unsupported because it had no holder/liquidity source; launchpad graduation is
the enforceable atomic listing path. Rejected proposals finalize durably under
declared ABI semantics instead of being mistaken for transaction failures.
Referral and trading rewards now consume one shared epoch cap.

Prediction-market complete-set minting allocates one deposit across outcomes
instead of charging the full deposit to every outcome. Every buy, sell, mint,
and redeem updates an exact aggregate cost. Voiding snapshots immutable trader
and LP pools so claims are pro-rata and independent of claim order, while
legacy markets without enough source data fail closed. Trading and minting both
reject the exact close slot.

The first exact expanded run then exposed a client-side consequence of the new
custody rule: two native-quote sweep buys reserved aggregate taker fee but not
Core's additional one-unit-per-lot fragmentation bound and correctly failed
before mutation. Margin, prediction, governance, rewards, router, analytics,
oracle refresh, and live WebSocket execution still passed. The browser client
and volume journey now calculate the same exact floor-notional, proportional
fee, and maximum-fill-count bound as Core; escrow enforcement was not relaxed.

The runtime upgrade lifecycle also retains the last governed ABI until an
explicit `SetContractAbi` action replaces it. Previously an immediate or staged
code upgrade cleared the ABI, creating a window where non-trapping child-call
error codes could lose their declared rollback semantics. The preserved-chain
Testnet rollout does not rely on that window: while all four validators are
stopped, the existing guarded Testnet-only repair reads only the signed release
bundle and atomically replaces each wrapped-asset, oracle, DEX, rewards,
prediction, and SporePump contract's code and ABI while preserving its address,
owner, balance, storage, prior hash, and chain history. It is dry-run checked,
idempotent, and must produce identical post-repair contract/storage evidence on
all four validators before restart.
